# Autoresearch program (oral-cavity-classifier)

Human-facing contract for Karpathy-style loops: what we optimize, what may change, how we score, and when we stop. The agent reads this file; immutable evaluation code is not edited during search.

## Overnight batches (no babysitting, no LLM required between runs)

Karpathy’s repo also does **not** embed an LLM: you decide the experiment queue **once**, then the machine runs **train → eval → score** for each item. An LLM (or you) is only needed if you want **adaptive** “next hypothesis from last loss curve” — that is optional, not required for unattended runs.

**This repo:** `autoresearch_loop.py run` already executes **many** configs **in order** in a **single** process. You pre-create JSON files under `experiment_configs/` (or reuse existing ones), then start **one** command and walk away:

```bash
ml/training/venv_pytorch/bin/python ml/training/notebooks/autoresearch_loop.py run \
  --patientwise-v3 \
  --recipe ml/training/notebooks/experiment_configs/autoresearch_overnight_recipe.txt \
  --run-id-prefix overnight_20260328
```

Or pass paths inline (no recipe file):

```bash
... autoresearch_loop.py run --patientwise-v3 --run-id-prefix o1 \
  --config a.json b.json c.json d.json e.json f.json g.json h.json i.json j.json
```

Planning work (writing 10 JSONs or one recipe) happens **before** the night; the loop does not stop for manual edits between experiments.

## Cursor agent: next experiment from the last ledger row

To have **Cursor** propose the next config after a run (adaptive step), dump context the model can read, then ask in chat for one new JSON:

```bash
ml/training/venv_pytorch/bin/python ml/training/notebooks/autoresearch_loop.py agent-context
```

See [AUTORESEARCH_CURSOR_AGENT.md](AUTORESEARCH_CURSOR_AGENT.md) for the full workflow. JSON variant: `--output-format json`. Optional: `-o .../last_context.md` to save and `@`-reference in Cursor.

## Objective

Improve **binary screening** quality on frozen benchmarks while respecting guardrails. Primary goal: maximize **sensitivity at fixed high specificity** on the pooled TM master (`TM` in eval JSON).

## Immutable (do not modify during autoresearch)

- Frozen test manifests and loaders: `frozen_test_sets.py`, JSON under `frozen_test_sets/`.
- Evaluation script semantics: `evaluate_on_frozen_sets.py` (same splits, same metrics).
- Patient-wise leakage rules baked into data (no relaxing splits mid-search).

## Mutable (agent / loop may change)

- Training JSON configs passed to `train_experiment.py`: loss (`ce` / `focal`), `focal_gamma`, `cancer_weight_multiplier`, `label_smoothing`, optimizer, LR schedule knobs, `dropout_rate`, `epochs`, `batch_size`, `strategy`, `freeze_bn`, seeds via ensemble training.
- **Training data:** By default, binary training uses **`get_all_train_val_for_training_v3`** (same pool as `train_binary_ensemble_patientwise.ipynb`): patient-wise roots `~/dev/oral_cavity_5class_dataset_patientwise` and `~/dev/oral_cavity_smart_ii_patientwise` plus TB/TC manifests — **not** the image-wise `~/dev/oral_cavity_5class_dataset` tree. Opt out only with `"patientwise_v3": false` in JSON or `--legacy-image-wise-5class` (not recommended).
- **Not** in scope for v1 loop: editing Flutter `ScreeningConfig` (app thresholds); promotion may recommend threshold updates separately.

## Scoring contract

- **Primary metric:** `TM.auroc` tie-break with **`TM.sens_at_90spec`** (higher is better). If your team standardizes on `sens_at_85spec`, switch primary in `autoresearch_loop.py` only after updating this section and re-baselining.
- **Guardrails (candidate fails if any violated vs baseline):**
  - `TM.auroc` must not drop by more than **0.01** absolute vs baseline.
  - `T5.auroc` (if present) must not drop by more than **0.02** absolute vs baseline.
- **Keep / revert:**
  - **Keep** if primary improves and guardrails pass.
  - **Revert** otherwise (discard candidate for promotion; ledger still records the run).

## Runtime budget (M1)

- Default training wall-clock target per experiment: **25–45 minutes** (use config `epochs` / early stopping to stay in band).
- Eval after each train: short (frozen sets only).

## Stop conditions

- **Iteration cap:** set per batch (e.g. 20–40); orchestrator `--max-iterations`.
- **No improvement:** optional stop after N consecutive non-improvements (`--patience-iters`).
- **Manual stop:** Ctrl+C; resume via ledger (see `results/autoresearch/README.md`).
